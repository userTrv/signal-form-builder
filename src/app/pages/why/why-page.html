Why Signal Forms?

The same sign-up form written twice — once with typed Reactive Forms, once with Signal Forms from @angular/forms/signals. It is the form behind the sign-up example: async username check, password confirmation, and a “seats” field that exists only for the Team plan.

Status: in the installed Angular 22.2 typings every Signal Forms API used here is marked @publicApi 22.0. They were experimental in Angular 20–21 and their shape changed between those versions (this project was written against the typings in node_modules, not against older blog posts). The only experimental piece I found is the WebMCP integration, which this project does not use.

What gets simpler

  • The model is the source of truth. The form wraps a plain signal<Signup>; there is no value vs getRawValue() split caused by disabled controls, and the value type is the model type.
  • Conditional logic is declarative. hidden, disabled, readonly and required(…, { when }) are reactive functions instead of valueChanges subscriptions calling setValidators and updateValueAndValidity.
  • Cross-field errors land where they belong. validate(p.confirmPassword, …) reads valueOf(p.password); in Reactive Forms the error of a group validator lives on the group.
  • Async validation is built on resource(). Debounce is an option; a newer request aborts the previous one through an AbortSignal; pending() is a signal.
  • All state is signals (valid(), touched(), errors(), errorSummary()), which fits zoneless, OnPush-by-default Angular 22 without statusChanges plumbing.
  • Custom controls are small. A component with value = model() implements FormValueControl; no ControlValueAccessor, no NG_VALUE_ACCESSOR. The rating, phone, file and checkbox-group controls in this project are 50–90 lines each.
  • Rules are plain functions over paths, which is what made a schema → rules translator practical: the whole mapping in this project (engine/model/build-rules.ts) is about 200 lines.

What is still missing or needs care

  • It is new. Stable only since Angular 22; libraries, examples and team experience are still catching up, and code written for the v20/v21 experimental API needs changes (the binding directive was renamed along the way and is [formField] now; hidden(path, fn) is deprecated in favour of hidden(path, { when })).
  • No computed fields. There is no rule for “this field's value is derived from others”. This project marks such fields readonly and writes the derived values back into the model from one effect (a pure, structurally-sharing applyComputed).
  • Hidden fields keep their values. hidden() removes a field from validation and from the parent's validity, but not from the model — strip what you do not want to send.
  • Array rows are tracked by object identity (a symbol stored on each row object). Replacing a row with a copy (JSON round-trip, structuredClone) makes it a new row with fresh touched/dirty state. Spread-copies keep the symbol, so immutable updates are fine.
  • Static typing needs a static model. For schemas that only exist at runtime the model is a Record<string, unknown> and paths are looked up by key, which needs casts (kept in one file here). For schemas written as const this project recovers full typing at the type level.
  • Migration is incremental, not free. @angular/forms/signals/compat provides compatForm and SignalFormControl to mix both worlds; this project does not use them, so I cannot vouch for them beyond their typings.
  • Async validators run only after the field's synchronous validators pass (documented behaviour).
